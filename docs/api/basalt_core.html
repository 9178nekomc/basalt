final class BC implements Layout¶

批×通道布局标记，同时用于批×特征与批×类别

BC 表示二维张量，第 0 轴为批（batch），第 1 轴为通道（channels）。源码注释同时声明该布局复用为「批 × 特征」与「批 × 类别」，因此全连接层的输入输出、以及分类头的 logits 都落在这一标记上。

该类没有成员，构造器为 private，运行期不存在任何实例。它只出现在泛型参数位置，例如 Tensor<BC>，用来在编译期固定轴的含义。basalt.nn 中的 CNN 以 Tensor<BC> 表示输出与目标，Flatten 用它在 BCHW 与 BC 之间转换。

示例
Tensor<BC> logits = Tensor.ofBC(2, 3, 0.5, 0.25, 0.75, 0.1, 0.2, 0.3);
int batch = logits.dimension(0);
int classes = logits.dimension(1);

注意

仅做编译期标记：不产生对象、不占用堆内存、不带来运行时分派开销。

注意

构造器私有，无法实例化；类型检查全部发生在 javac 阶段。

参见：basalt.core.Layout, basalt.core.Tensor, basalt.nn.CNN

final class BCHW implements Layout¶

批×通道×高×宽布局标记，卷积网络的图像张量

BCHW 表示四维张量，轴序为 batch、channels、height、width。这是卷积与池化层的工作格式：同一批内的某个通道构成一张连续的特征图，通道维位于空间维之前。

Tensor.ofBCHW 与 Tensor.zerosBCHW 产生携带该标记的实例。Conv2D、MaxPooling2D 的 forward 与 backward 均以 Tensor<BCHW> 收发数据，CNN 则把它作为训练输入。

与其余三个标记相同，该类没有成员，构造器为 private，运行期不产生实例，只约束泛型参数。

示例
Tensor<BCHW> images = Tensor.zerosBCHW(4, 3, 32, 32);
int channels = images.dimension(1);
int height = images.dimension(2);

注意

仅做编译期标记，无运行期表示与开销。

注意

轴序固定为批在最前，因此批切片在存储中连续，sliceBatch 可用单次 arraycopy 完成。

参见：basalt.core.Layout, basalt.core.BHW, basalt.nn.Conv2D

final class BHW implements Layout¶

批×高×宽布局标记，省略通道轴的三维图像张量

BHW 表示三维张量，轴序为 batch、height、width。与 BCHW 的差别只在于没有通道轴，适合灰度图或已合并通道的中间结果。

Tensor.ofBHW 是唯一产生该标记的工厂方法；本包未提供对应的 zeros 变体，需要全零张量时可先构造 double 数组再传入。

该类没有成员，构造器为 private，运行期不产生实例，仅在泛型参数位置出现。

示例
double[] pixels = new double[2 * 8 * 8];
Tensor<BHW> gray = Tensor.ofBHW(2, 8, 8, pixels);
int rank = gray.rank();

注意

仅做编译期标记，无运行期表示与开销。

注意

Tensor<BHW> 与 Tensor<BCHW> 是不同类型，轴数不同的张量无法互相赋值。

参见：basalt.core.Layout, basalt.core.BCHW

final class BSF implements Layout¶

批×序列×特征布局标记，序列模型的标准输入

BSF 表示三维张量，轴序为 batch、sequence（时间步）、features。同一时间步的特征在存储中相邻，循环层按时间步推进时每次读取一段连续内存。

Tensor.ofBSF 与 Tensor.zerosBSF 产生该标记的实例。LSTM、GRU、SelfAttention、SequenceNetwork 与 GradientCheck 都以 Tensor<BSF> 作为输入、输出与梯度的载体。

该类没有成员，构造器为 private，运行期不产生实例，仅在泛型参数位置出现。

示例
Tensor<BSF> batch = Tensor.zerosBSF(8, 16, 32);
int steps = batch.dimension(1);
int features = batch.dimension(2);

注意

仅做编译期标记，无运行期表示与开销。

注意

序列轴位于批轴之后，因此按批切片仍是一段连续存储。

参见：basalt.core.Layout, basalt.nn.LSTM, basalt.nn.SequenceNetwork

sealed interface Layout¶

张量维度顺序的编译期标记接口，只约束泛型参数

Layout 是 sealed 接口，permits 子句把实现者限定为 BCHW、BHW、BC、BSF 四个类。接口本身不声明任何方法，四个实现类也没有成员，构造器全部为 private，因此运行期不存在 Layout 的实例，标记只以类型参数的形式存在。

它的作用是让轴的含义进入类型系统：Tensor<S extends Layout> 用 S 记录维度顺序，卷积层接收 Tensor<BCHW>、序列层接收 Tensor<BSF>，把错误的张量传给错误的层会在编译期失败，而不是在运行期产生形状异常。

由于没有实例与虚方法，标记不带来对象分配、内存占用或调用开销，形状与轴数仍由 Tensor 内部的 int[] 在运行期保存。

示例
Tensor<BCHW> images = Tensor.zerosBCHW(2, 3, 8, 8);
Tensor<BSF> sequence = Tensor.zerosBSF(2, 4, 16);
// images 与 sequence 是不同类型，编译器拒绝互相赋值
int imageRank = images.rank();
int sequenceRank = sequence.rank();

注意

sealed 限定实现者，第三方无法新增布局；新增布局需要修改 permits 子句。

注意

标记不含任何运行期信息，轴数仍需通过 Tensor.rank() 获取。

参见：basalt.core.Tensor, basalt.core.BC, basalt.core.BCHW, basalt.core.BHW, basalt.core.BSF

final class MatMul implements AutoCloseable¶

矩阵乘法引擎：标量基准与分块并行的 SIMD 实现

实例封装一个 ForkJoinPool 与一个线程数提示值。multiply 在该池上派发按行切分的 RowTask；当工作量 rows * columns * shared 达到 100000000 且原生库可用时，改走 Rust 的 AVX2/FMA 内核，并把同一线程数提示传给原生侧，原生内核抛 IllegalStateException 时静默回退到 Java 路径。

Java 路径先把右操作数转置成列主序副本，使每个输出元素的点积在两个数组上都是连续读取，再按行二分递归切分，叶子节点逐元素调用 VectorMath.dot。切分在行数不超过 8 或子任务工作量不超过 65536 时停止。

线程数来源有三处：create() 取 Runtime.availableProcessors()，create(int) 取显式值，commonPool() 复用 JVM 公共池并把线程数记为可用核数。前两者拥有自己的池，close() 时关闭；commonPool() 的包装不拥有池。

示例
try (MatMul engine = MatMul.create(4)) {
    Matrix a = Matrix.zeros(512, 256);
    Matrix b = Matrix.zeros(256, 128);
    Matrix c = engine.multiply(a, b);
    int columns = c.columns();
}

注意

close() 只关闭 create 系列创建的池；对 commonPool() 的包装调用 close() 不产生任何效果。

注意

multiply 与 scalar 都校验内维相等，并检查输出元素数是否超过 Integer.MAX_VALUE。

注意

原生路径只在 NativeKernels.available() 为真且工作量达标时启用，失败时回退而非抛出 JNI 错误。

参见：basalt.core.Matrix, basalt.core.VectorMath, basalt.core.NativeKernels

方法

create() → MatMulstatic¶

按可用处理器数创建引擎

与 create(int) 的唯一差别是线程数来源：这里取运行环境的可用处理器数作为池的并行度。引擎拥有该池，close() 会将其关闭。

返回

持有独立 ForkJoinPool 的引擎，线程数等于 Runtime.availableProcessors()

create(int threads) → MatMulstatic¶

按指定并行度创建引擎

源码注释说明该重载用于扩展性基准测试：固定并行度可以让不同规模的乘积在同一线程预算下比较。该值同时作为原生内核的线程数提示传给 NativeKernels。

参数

  • threads (int) – ForkJoinPool 并行度，必须为正

返回

持有独立线程池的引擎，线程数等于 threads

抛出

  • IllegalArgumentException – threads 小于等于 0

commonPool() → MatMulstatic¶

包装 JVM 公共 ForkJoinPool 的引擎

复用 ForkJoinPool.commonPool()，不新建线程；ownsPool 为 false，因此 close() 不会关闭公共池，实例可以随用随弃。Matrix.matMul 每次调用都走这条路径。

注意

公共池与同进程内其他 ForkJoinTask 共享，并行度不受本引擎控制。

返回

不拥有线程池的引擎，线程数记为可用核数

scalar(Matrix left, Matrix right) → Matrixstatic¶

三重循环的标量乘法基准实现

静态方法，不使用线程池也不调用 SIMD，按 i、j、k 顺序逐元素累加，作为正确性与速度的参照。源码注释明确其定位是 baseline，不应作为生产路径。

注意

结果通过公开构造器装入，会再克隆一次输出数组。

参数

  • left (Matrix) – 左操作数，形状 m×k

  • right (Matrix) – 右操作数，形状 k×n，行数须等于 left.columns()

返回

形状为 m×n 的新矩阵

抛出

  • IllegalArgumentException – 内维不匹配，或输出元素数超过 Integer.MAX_VALUE

  • NullPointerException – 任一操作数为 null

multiply(Matrix left, Matrix right) → Matrix¶

按规模选择原生内核或分块并行 Java 路径

工作量以 long 计算为 rows * columns * shared。达到 100000000 且原生库可用时调用 NativeKernels.gemmChecked，并用 Matrix.wrap 直接接管其输出缓冲区；否则转置右操作数后在池上执行 RowTask，逐元素用 VectorMath.dot 计算。

注意

原生路径的线程数取自构造引擎时的 threads 字段。

注意

Java 路径每次调用都会分配一份右操作数的转置副本。

参数

  • left (Matrix) – 左操作数，形状 m×k

  • right (Matrix) – 右操作数，形状 k×n，行数须等于 left.columns()

返回

形状为 m×n 的新矩阵

抛出

  • IllegalArgumentException – 内维不匹配，或输出元素数超过 Integer.MAX_VALUE

  • NullPointerException – 任一操作数为 null

close()¶

关闭自有的线程池

仅当引擎由 create() 或 create(int) 创建时调用 pool.shutdown()；commonPool() 的包装因 ownsPool 为 false 而不做任何事。方法幂等，可重复调用。

注意

关闭后不应再调用 multiply，池已不再接受新任务。

final class Matrix¶

行主序、单块 double 数组承载的可变矩阵

全部元素存放在一个连续的 double[] 中，元素 (r, c) 的偏移由 index 计算为 r * columns + c，因此同一行在内存中相邻，按行遍历具有良好的局部性。行数、列数与数组引用都是 final，形状不可变而元素可变。

构造器与 fromRows 都校验维度为正、长度等于 rows * columns，并克隆传入数组；zeros 只校验维度后分配已清零的数组。data() 返回内部数组本体，toArray() 返回副本，二者的取舍决定调用方能否观察到后续写入。

乘法不在本类实现：matMul 每次调用都构造一个绑定 ForkJoinPool.commonPool() 的 MatMul 包装对象并转发，因此不持有长期线程资源，也不需要关闭。

示例
Matrix m = Matrix.fromRows(new double[][]{{1, 2}, {3, 4}});
m.set(0, 1, 5.0);
double[] live = m.data();
double[] safe = m.toArray();
Matrix product = m.matMul(m.transpose());

注意

data() 暴露内部存储，写入该数组等同修改矩阵；需要快照时使用 toArray() 或 copy()。

注意

构造器接受外部数组时会克隆，后续修改源数组不会影响矩阵。

注意

形状校验用 long 计算 rows * columns，超过 Integer.MAX_VALUE 时抛出 IllegalArgumentException。

参见：basalt.core.MatMul, basalt.core.Tensor, basalt.core.VectorMath

构造器

Matrix(int rows, int columns, double[] data)¶

校验形状后克隆数组内容构造矩阵

校验顺序为维度、null、长度：先确认 rows 与 columns 为正，再检查数组非空，最后比对长度与乘积。通过后调用 clone，因此矩阵与调用方不共享存储。

注意

传入数组不会被持有，构造完成后修改源数组不影响矩阵内容。

参数

  • rows (int) – 行数，必须为正

  • columns (int) – 列数，必须为正

  • data (double[]) – 行主序元素，长度必须等于 rows * columns，构造时被克隆

抛出

  • IllegalArgumentException – 维度非正、长度不符，或元素总数超过 Integer.MAX_VALUE

  • NullPointerException – data 为 null

方法

zeros(int rows, int columns) → Matrixstatic¶

创建指定形状的全零矩阵

只做维度校验，随后按 rows * columns 分配新数组；初值 0.0 由 JVM 保证，不再逐元素填充，因此成本与元素数成线性关系但常数很小。

参数

  • rows (int) – 行数，必须为正

  • columns (int) – 列数，必须为正

返回

新分配的全零矩阵

抛出

  • IllegalArgumentException – 维度非正，或元素总数超过 Integer.MAX_VALUE

fromRows(double[][] rows) → Matrixstatic¶

由二维数组按行拷贝构造矩阵

以第一行的长度作为列数，逐行用 System.arraycopy 拷入连续缓冲区。长度不一致会在该行处立即失败，不做截断或补零，因此可以安全地用于读入外部表格数据。

注意

空数组与零长度行都视为非法，矩阵不接受零元素。

参数

  • rows (double[][]) – 非空二维数组，各行长度必须相同

返回

行数等于 rows.length 的矩阵

抛出

  • IllegalArgumentException – 数组为空、某行长度不一致，或元素总数超过 Integer.MAX_VALUE

final class ModelFormatException extends RuntimeException¶

.bsl 流截断、损坏或版本不兼容时抛出的非受检异常

ModelFormatException 继承 RuntimeException，方法签名里不出现受检声明，因此解码路径可以把格式错误从深层字段读取处直接向上抛出，无需逐层包装。捕获方只拦这一个类型即可覆盖全部 .bsl 解析失败。

触发点集中在两处：ModelReader 的长度与剩余字节校验，以及 ModelKind.fromCode 与 ModelCodec 的魔数、版本、长度和 CRC32C 校验。类本身不携带额外字段，异常消息是唯一的诊断信息。

注意

非受检异常：编译器不强制捕获，也不会被 try-with-resources 自动包装。

注意

保存路径同样复用它表示超过容器上限，因此该类型在读、写两侧都会出现。

参见：basalt.core.ModelReader, basalt.core.ModelKind, basalt.io.ModelCodec

enum ModelKind¶

可持久化模型族的稳定线格式标识码

每个常量的 code 就是 .bsl 容器头部第三个 int 字段的取值：ModelCodec.save 写入它，load 读出后再经 fromCode 还原成常量。码值从 1 开始连续分配到 32，与声明顺序一致，中间没有空洞。

常量对应实现 Persistable 的模型族：经典估计器与预处理器在 basalt.ml，序列模型在 basalt.nn。3.4 起共 32 个族，按用途分为网络与集成模型（1 至 11）、预处理与流水线（12 至 17）、核方法与无监督（18 至 23）、特征工程（24 至 26）、线性与树模型（27 至 32）。

ModelCodec.readPayload 用 switch 把常量分派到各族的静态 read 方法，新增模型族必须同时扩展枚举与分派表。

注意

码值是线格式的一部分：已发布的取值不可修改或复用，否则旧文件会被解成错误的模型族。

注意

fromCode 对未定义码抛 ModelFormatException，不返回 null。

注意

枚举顺序被 values() 与 fromCode 的线性扫描依赖，重排常量不影响码值，但会影响扫描顺序。

注意

Pipeline 的 payload 内嵌子步骤的码值，因此新增预处理类型后旧读取方无法解开含该步骤的流水线文件。

参见：basalt.core.Persistable, basalt.io.ModelCodec

final class ModelReader¶

与 ModelWriter 配对的大端、带越界校验的读取器

读取位置由内部 ByteBuffer 维护，每次读取前先比较剩余字节，不足即抛 ModelFormatException，因此截断的负载不会读到半个字段，也不会产生越界访问。字段顺序完全由各模型族的 read 方法决定，读取器本身不记录任何模式。

byte[] 构造器包装整个数组，位置从 0 起；ByteBuffer 构造器在 position() 到 limit() 之间做切片，不复制也不移动源缓冲区。切片固定按大端解释，即使源缓冲区被设成小端也不改变读取结果。

注意

所有方法按大端解释字节，与 ModelWriter 的写入顺序一致。

注意

requireFullyConsumed 只在解码完成后调用一次，用于拒绝尾部多余字节。

注意

读取器不校验魔数、版本与 CRC32C，这些由 ModelCodec 在构造它之前完成。

参见：basalt.core.ModelWriter, basalt.io.ModelCodec, basalt.core.ModelFormatException

final class NativeKernels¶

通过 JNI 暴露的可选 Rust 内核集合

类初始化时按三级顺序寻找动态库：先看 -Djsl.native.path 指定的文件，再从 classpath 的 /native/<platform>/ 资源解压到临时目录，最后回退到 java.library.path 上的 basalt_native。三步全部失败时 available() 为 false，调用方改走纯 Java 实现。

公开方法分两类：*Checked 系列把原生状态码翻译成布尔值，0 表示成功、非 0 表示参数或形状被拒绝，调用方据此回退；gemmChecked 是唯一把失败翻译成异常的方法。所有数组参数都是行主序的扁平 double[]、int[]、byte[]，不涉及张量句柄，也不进入计算图。

createHistogramSession 返回不透明 long 句柄，把分箱矩阵、梯度与二阶梯度常驻原生内存，之后每个树节点只传样本下标与活跃特征表。句柄需要显式销毁，否则原生内存保留到进程结束。

示例
import basalt.core.NativeKernels;

public final class NativeProbe {
    public static void main(String[] args) {
        if (!NativeKernels.available()) {
            System.out.println("unavailable: " + NativeKernels.loadError());
            System.out.println("expected at " + NativeKernels.libraryPath());
            return;
        }
        double[] data = {0.0, 0.0, 1.0, 1.0, 10.0, 10.0, 11.0, 11.0};
        double[] centers = {0.0, 0.0, 10.0, 10.0};
        int[] assignments = new int[4];
        double[] distances = new double[4];
        boolean ok = NativeKernels.kmeansAssignChecked(
                data, centers, 4, 2, 2, 1, assignments, distances);
        if (!ok) {
            throw new IllegalStateException("native kernel rejected the shapes");
        }
        for (int row = 0; row < assignments.length; row++) {
            System.out.println(row + " -> cluster " + assignments[row]
                    + " (squared distance " + distances[row] + ")");
        }
    }
}

注意

原生库不可用时，除 version() 之外的 public 方法都会因缺少本地实现抛 UnsatisfiedLinkError；调用前必须先判断 available()。

注意

available()、loadError()、libraryPath() 在类初始化时一次确定，运行期不会因重新放置库文件而改变。

注意

直方图会话句柄必须在训练结束时调用 destroyHistogramSession；会话内部以 f32 桶累加，与一次性路径的 f64 累加存在末位差异。

注意

原生侧按线程数缓存 rayon 线程池，threads 参数只影响本次调用的并行度，不改变池的生命周期。

参见：basalt.nativebridge.NativeLibrary, basalt.core.MatMul, basalt.ml.HistogramGradientBoosting

final class Tensor<S extends Layout>¶

布局由类型参数约束的可变连续张量

元素存放在单个连续 double[] 中，按行主序线性化：index 从第 0 轴起依次执行 index = index * shape[axis] + coordinate，最后一维变化最快。形状以 int[] 保存并在构造时克隆，shape() 返回的同样是副本。

布局不是运行期字段，而是泛型参数 S。Tensor<BCHW> 与 Tensor<BSF> 是不同类型，卷积层与序列层因此在编译期就无法互相传参；轴数与各轴长度仍由 shape 数组在运行期保存，可经 rank 与 dimension 读取。

of 系列工厂克隆传入的变长参数数组，zeros 系列直接分配已清零的数组；data() 返回内部数组本体，toArray() 与 copy() 才产生副本。本类属于 basalt.core，是神经网络层与经典估计器共用的数值容器，不参与计算图。

示例

double v = logits.get(1, 2);
Tensor<BC> head = logits.sliceBatch(0, 1);
Tensor<BCHW> blank = Tensor.zerosBCHW(1, 3, 32, 32);
int rank = blank.rank();

注意

data() 暴露内部存储，写入等同修改张量；需要快照时使用 toArray()。

注意

sliceBatch 复制数据而非创建视图，返回的张量与源张量不共享存储。

注意

dimension(int) 不做轴范围校验，越界由数组访问抛出 ArrayIndexOutOfBoundsException。

注意

与 basalt.torch.Tensor 无关：后者是持有原生句柄、参与计算图的类型。

参见：basalt.core.Layout, basalt.core.Matrix, basalt.torch.Tensor

final class VectorMath¶

被乘法、距离、优化器与归一化共用的 SIMD 原语

每个核函数都写成向量主循环加标量尾段：主循环以 DoubleVector.SPECIES_PREFERRED 的通道数步进，剩余不足一个向量的部分用标量循环补齐。因此任意长度与非对齐偏移都是安全的，调用方不需要把数组补齐到通道数的整数倍。

累加普遍使用向量 fma 或 Math.fma，把乘加融合成一条指令并省去一次中间舍入。所有函数都是静态方法、无内部状态，也不分配数组；axpy 与 scaleInPlace 直接写回目标。多个线程可并发调用，前提是各线程操作不同的数组区间。

本类不做 NaN 与无穷大的特殊处理：输入含 NaN 时结果按 IEEE 754 传播；norm 由 sumSquares 开方得到，未做溢出保护。唯一的零值保护出现在 clipNorm，它在范数为 0 时跳过缩放以避免除零。

示例
double[] a = {1.0, 2.0, 3.0};
double[] b = {0.5, 0.5, 0.5};
double numerator = VectorMath.dot(a, 0, b, 0, a.length);
VectorMath.axpy(-1.0, b, a);
double d2 = VectorMath.squaredEuclidean(a, 0, b, 0, a.length);
double before = VectorMath.clipNorm(a, 1.0);

注意

static final class NativeKernels.HistogramSessionHandle implements AutoCloseable¶

持有原生直方图会话指针的可关闭句柄

实例把 histogramSessionCreate 返回的指针存进 AtomicLong，并通过 Cleaner 注册清理动作。清理时以 getAndSet(0) 取出指针，仅在非零时调用 destroyHistogramSession，因此销毁最多发生一次。

这样即使在建树过程中抛出异常、调用方忘记关闭，会话也会在句柄不可达后被回收；显式 close() 则把回收时机提前到确定的位置。句柄关闭后 handle() 返回 0，此时不能再把该值传给 updateHistogramSession 等会话方法。

示例
long session = NativeKernels.createHistogramSession(bins, gradients, hessians, features, maxBins);
try (NativeKernels.HistogramSessionHandle handle =
        new NativeKernels.HistogramSessionHandle(session)) {
    NativeKernels.updateHistogramSession(handle.handle(), gradients, hessians);
}

注意

实现 AutoCloseable，配合 try-with-resources 使用可确定性地释放原生会话。

注意

close() 幂等：清理动作已执行时再次调用取到的是 0，不会重复销毁。

注意

构造不做非零校验，传入 0 会得到一个已失效的句柄，所有会话方法都会失败。

注意

真实指针只保存在 AtomicLong 中，句柄对象本身不被原生侧引用。

参见：basalt.core.NativeKernels, basalt.ml.HistogramGradientBoosting

private static final class MatMul.RowTask extends RecursiveAction¶

按行区间切分的 ForkJoin 乘法子任务

MatMul.multiply 在未走原生内核时先转置右操作数，再把整个行区间封装成 RowTask 交给 pool.invoke；任务只持有数组引用与区间下标，所有子任务共享同一个 output 数组，各自只写自己负责的行。

compute() 是 RecursiveAction 的分治入口：行数不超过 ROW_BLOCK（8）或区间工作量不超过 WORK_THRESHOLD（65536）时直接计算，否则从中点二分并用 invokeAll 提交两个子任务并等待返回。

方法

compute()¶

ForkJoin 调度入口：二分区间或就地计算行块

由 ForkJoinPool 在 MatMul.multiply 的 pool.invoke 之后调用，也可能由父任务通过 invokeAll 提交。判定为叶任务时转入 computeBlock，用 VectorMath.dot 逐列填充共享 output 数组；否则按行区间对半拆成两个 RowTask 并等待二者结束。

返回

无返回值；结果写入构造时传入的共享 output 数组
