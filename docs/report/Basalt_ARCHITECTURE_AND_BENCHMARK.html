Basalt 终极架构与性能基准测试报告

版本：Basalt 2.4（.bsl v2；Rust 张量引擎 v0.2 + basalt.torch） 运行时：OpenJDK 21（--release 21，jdk.incubator.vector）+ Rust 1.98（JNI） 依赖：Java 0；原生侧 jni + rayon + slotmap + matrixmultiply 验证入口：./verify.sh；基准入口：./benchmark.sh v5 现代训练栈（21 原生算子、CNN/Transformer、类型安全管线、JFR）见 README.md 第 5 节 与 report/Basalt_VS_SKLEARN.md 第 3.5 节。

0. 执行摘要

本轮升维在原有 Basalt 之上完成了三件事：

  1. 广度：直方图梯度提升（XGBoost 深度优先 / LightGBM 叶优先）、随机森林（分类 + 回归 + OOB）、

K-Means++（并行分配 + 重启）、PCA（协方差 Jacobi + Gram 对偶 + 白化）、高斯朴素贝叶斯。

  1. 深度：LSTM、GRU、VanillaRNN 的完整 BPTT，单头自注意力（含 causal mask）的 Q/K/V 与

Softmax 反向，以及可端到端训练的 SequenceNetwork（池化头、损失、梯度裁剪、小批量）。

  1. 速度与内存：SIMD 内核、直方图分裂、并行树/聚类、映射式数据管线、CRC32C 校验的

.bsl v2 全模型序列化。

关键实测结果（本机，8 逻辑核，JDK 21，-Xmx2g）：

2. 总体架构

2.1 分层

basalt.core     Matrix / Tensor<S extends Layout> / MatMul / VectorMath
             ModelKind / ModelWriter / ModelReader / Persistable
   │
   ├── basalt.ml    Estimator 实现：线性、KNN、树、提升、KMeans、PCA、GNB
   │              BinnedFeatures（共享分箱）
   │
   ├── basalt.nn    Layer<I,O>：Dense / Conv2D / LSTM / GRU / RNN / SelfAttention
   │              SequencePool / SequenceNetwork / GradientCheck
   │
   ├── basalt.data  DataLoader（BasaltD 顺序 + 映射 + 洗牌）/ Normalization
   │
   └── basalt.io    ModelCodec（.bsl v2 容器，CRC32C）

依赖方向严格单向：core 不依赖任何上层；ml/nn/data 只依赖 core；io 依赖 core + ml + nn 做类型分发。没有包级循环。

2.2 类型系统

抽象作用编译期保证
Layout + BCHW/BC/BSF/BHW张量布局标记Tensor<BCHW> 不能传给 Layer<BSF,BSF>
Tensor<S>连续 double[]，行主序构造时校验 shape 与元素数
Layer<I,O>可微变换forward/backward 的布局在类型上闭合
Estimator经典模型统一契约fit(Matrix,double[]) / predict(Matrix)
Persistable可序列化模型kind() 与 write(ModelWriter)
ParameterRef参数与梯度的只读视图梯度检验、裁剪、序列化共用

NeuralNetwork 的分阶段 Builder 把“图像层之后必须先 Flatten”编码进类型： ImageBuilder.add(Dense) 根本不存在，VectorBuilder 只能由 add(Flatten) 产生。 SequenceNetwork.Builder.add 的签名是 <L extends Layer<BSF,BSF>>，传入 Dense （Layer<BC,BC>）无法通过编译。

2.3 数值表示

  • 统一 double，不引入半精度/量化；所有入口拒绝 NaN/Inf。
  • 张量/矩阵使用单个连续数组，避免 double[][] 的指针追逐与行碎片。
  • 所有尺寸计算先提升到 long，超过 Integer.MAX_VALUE 立即失败，避免溢出成负数。

3. 数值内核与矩阵乘

3.1 SIMD 原语

VectorMath 提供 dot、squaredEuclidean、manhattan、axpy、scaleInPlace、 sumSquares、norm、maxAbs、clipNorm。每个 kernel 都是 “向量主循环 + 标量尾段”，支持任意长度与非对齐偏移。

Parameter 的 SGD 与 Adam 也走 SIMD：

m_t = β₁ m_{t-1} + (1-β₁) g_t
v_t = β₂ v_{t-1} + (1-β₂) g_t²
θ_t = θ_{t-1} - η · (m_t/(1-β₁ᵗ)) / (sqrt(v_t/(1-β₂ᵗ)) + ε)

Adam 的逐元素运算全部用 DoubleVector 完成，避免 4 次数组往返。

3.2 矩阵乘实现

MatMul.multiply：

  1. 将右矩阵转置为 Bᵀ（行主序），使内积两侧都连续；
  2. 按行块递归拆分（RecursiveAction），工作量阈值 65 536；
  3. 每个输出元素调用 VectorMath.dot，FMA 累加；
  4. 输出仍为行主序 Matrix。

标量基线是朴素三重循环，内层按列访问 B，缓存不友好。这解释了为什么加速比随 n 增大：

  • n=64：转置与 ForkJoin 的固定开销大于收益，0.97×；
  • n=256：20.4×；
  • n=512：56.5×，27.9 GFLOP/s；
  • n=1024：47.9×，回落到 23.1 GFLOP/s——转置一次要写 8 MiB，且工作集超出 L2/L3，

进入内存带宽受限区。

线程扩展（512³）：

线程耗时 (ms)GFLOP/s相对 1 线程
128.519.411.00×
218.6414.401.53×
413.2520.252.15×
810.5925.352.69×

8 线程只有 2.7×，原因有三：转置是串行的；512² 输出与 512² 转置缓冲带来内存带宽压力； 8 个逻辑处理器可能包含 SMT，物理核数未单独确认。继续优化应做分块 + 复用转置缓冲， 而不是继续加线程。

4. 树模型

4.1 共享分箱：BinnedFeatures

对每个特征：

  1. 复制该列并排序；
  2. 在 maxBins-1 个分位点取相邻 order statistics 的中点作为候选阈值；
  3. 去重；
  4. 用二分查找把每个样本映射到桶号，存入 byte[]（无符号读取，支持最多 255 桶）。

阈值语义统一为 value <= threshold → 左。中点用 a/2 + b/2 计算，避免两个巨大有限数 相加溢出；若中点落在 [a,b) 之外（相邻 double 的极端情况），回退到 a，保证左支至少 包含 a、右支包含 b。

分箱只做一次，之后每个节点用直方图统计，避免“每个节点、每个特征都排序”的 O(n log n · p) 成本。

4.2 梯度提升的二阶推导

目标（XGBoost 正则化形式）：

Obj = Σ_i [ g_i f(x_i) + ½ h_i f(x_i)² ] + ½ λ Σ_j w_j² + γ T

对一个叶子，令 G = Σ g_i、H = Σ h_i，最优权重与最优值：

w* = -G / (H + λ)
Obj* = -½ · G² / (H + λ)

分裂增益：

Gain = ½ [ G_L²/(H_L+λ) + G_R²/(H_R+λ) - G²/(H+λ) ] - γ

实现位于 HistogramGradientBoosting.bestSplit。逻辑损失下：

p = σ(raw)
g = p - y
h = max(ε, p(1-p))

平方误差下 g = raw - y、h = 1。

4.3 两种生长策略

XGBoostLightGBM
顺序深度优先，递归到 maxDepth叶优先，优先队列按增益取最大叶
叶子预算由深度隐式决定（≤2^depth）显式 maxLeaves
特点树形规整、并行友好同样叶子数下通常更低损失，但更易过拟合
实现buildDepthWisebuildLeafWise + PriorityQueue<LeafCandidate>

直方图工作区是单个可复用数组：gradient/hessian/count 按 feature * maxBins + bin 切片。并行时每个特征写自己的切片，无锁、无冲突； 节点分裂不再分配直方图对象。

4.4 工业特性

  • featureFraction：每棵树随机选一部分特征参与分裂搜索。
  • validationFraction + earlyStoppingRounds：按行洗牌切分验证集，逐轮累计验证预测，

连续若干轮无改善则截断集成。

  • minSamplesLeaf、minChildWeight、lambda、gamma：完整正则化路径。
  • featureImportances()：按 gain × 样本数 累计并归一化。

4.5 随机森林

  • Bootstrap 采样 + 每节点 maxFeatures 特征子采样；
  • 分类：多数投票 + 概率；回归：树均值；
  • OOB：记录每棵树的 in-bag 掩码，对 OOB 样本做投票/平均，分类报准确率、回归报 R²；
  • 树之间完全独立，ForkJoinPool + IntStream.parallel 并行；
  • 复用同一套 DecisionTree 直方图内核，分类用 Gini/Entropy，回归用方差。

复杂度（n 样本、p 特征、B 桶、T 棵树、d 深度）：

阶段复杂度
分箱O(T · n p log n)（每棵树一次）
单节点直方图O(n_node · p_node)
单棵树O(n p log n + n p d)
森林O(T · 上式 / threads)

5. 无监督学习

5.1 K-Means++

种子选择：第一个中心均匀随机；之后每个样本以

P(x) = D(x)² / Σ_i D(x_i)²

被选中，其中 D(x) 是到已选中心的最近距离。理论上期望近似比为 O(log k)。

Lloyd 迭代：

  1. 并行分配：按行并行计算最近中心，写入 int[] assignments；
  2. 顺序累加簇和与计数（避免原子操作）；
  3. 空簇修复：从“样本数 > 1 的簇”中选距离最远的样本捐给空簇，同时更新两个簇的和；
  4. 计算中心位移平方和，shift² ≤ tol² 时停止；
  5. restarts 次独立运行，取 inertia 最小者。

复杂度 O(n k p · iterations · restarts)。分配步骤是主要成本，已并行化。

5.2 PCA：两种精确特征分解

协方差路径（JACOBI）：C = XcᵀXc/(n-1)，对 p×p 对称矩阵做循环 Jacobi。 每次旋转消去一对非对角元，收敛判据是非对角 Frobenius 范数相对矩阵范数小于 tol。 复杂度 O(n p² + p³ · sweeps)，适合 n ≫ p。

Gram 对偶路径（GRAM）：当 p ≫ n 时，协方差矩阵巨大且秩 ≤ n-1。改为分解 G = Xc Xcᵀ（n×n）：

G u = λ u
v = Xcᵀ u / sqrt(λ)
C v = Xcᵀ Xc Xcᵀ u / ((n-1) sqrt(λ))
    = Xcᵀ G u / ((n-1) sqrt(λ))
    = λ/(n-1) · v

所以 v 是 C 的特征向量，特征值为 λ/(n-1)。归一化后即主成分。 复杂度 O(n² p + n³ · sweeps)，适合 n ≪ p。

EigenSolver.AUTO 在 features > samples && samples ≤ 20 000 时选 GRAM，否则 JACOBI。 测试以 1e-9 容差断言两条路径的主成分投影一致；一次运行的实测最大绝对差为 1.5×10⁻¹⁴。

白化：投影除以 sqrt(λ_i)，使各主成分方差为 1。

6. 高斯朴素贝叶斯

对数域判别：

log P(c|x) = log π_c - ½ Σ_j [ log(2π σ_cj²) + (x_j - μ_cj)² / σ_cj² ]

预测时先减最大值再 exp，避免下溢；若所有类别的对数概率都是 -∞，回退到先验并重新归一化。

方差平滑采用相对尺度：

ε = var_smoothing × max(σ²)
σ² ← σ² + ε

而不是加一个绝对常数。否则同一份数据把单位从“米”换成“毫米”，平滑强度会相差 10⁶ 倍。 测试用 ×10⁶ 缩放验证了预测完全一致。

7. 序列模型与注意力

7.1 LSTM 前向

i_t = σ(W_i x_t + U_i h_{t-1} + b_i)
f_t = σ(W_f x_t + U_f h_{t-1} + b_f)
g_t = tanh(W_g x_t + U_g h_{t-1} + b_g)
o_t = σ(W_o x_t + U_o h_{t-1} + b_o)
c_t = f_t ⊙ c_{t-1} + i_t ⊙ g_t
h_t = o_t ⊙ tanh(c_t)

7.2 BPTT 推导

给定 dh_t（上层梯度 + 未来时间步梯度）：

dc_t = dh_t ⊙ o_t ⊙ (1 - tanh²(c_t)) + dc_{t+1} ⊙ f_{t+1}
df_t = dc_t ⊙ c_{t-1}
di_t = dc_t ⊙ g_t
dg_t = dc_t ⊙ i_t
do_t = dh_t ⊙ tanh(c_t)

d(·)_pre = d(·) ⊙ gate ⊙ (1 - gate)      (σ 门)
dg_pre   = dg ⊙ (1 - g²)                 (tanh 门)

dW_* += d(·)_pre ⊗ x_t
dU_* += d(·)_pre ⊗ h_{t-1}
db_* += d(·)_pre
dx_t += W_*ᵀ d(·)_pre
dh_{t-1} += U_*ᵀ d(·)_pre

关键在 dc_t/dc_{t-1} = f_t：只要遗忘门接近 1，梯度沿时间近似恒等传播。 h 路径仍然经过 o_t(1-tanh²)，但细胞状态提供了一条“常量误差传送带”。

7.3 GRU 前向与反向

z_t = σ(W_z x_t + U_z h_{t-1} + b_z)
r_t = σ(W_r x_t + U_r h_{t-1} + b_r)
n_t = tanh(W_n x_t + U_n (r_t ⊙ h_{t-1}) + b_n)
h_t = (1 - z_t) ⊙ n_t + z_t ⊙ h_{t-1}

反向的耦合点在 r ⊙ h：n_pre 对 h_j 的偏导包含 U_n[u][j] · r_j，对 r_j 的偏导 包含 U_n[u][j] · h_j。因此必须先对单元求和得到 d(rh)_j，再回传 dr_j 与 dh_j。 实现中 resetWeighted[j] = Σ_u U_n[u][j] · dn_pre_u，随后：

dr_j = d(rh)_j · h_j
dr_pre_j = dr_j · r_j(1-r_j)
dh_j += d(rh)_j · r_j + U_zᵀ dz_pre + U_rᵀ dr_pre
dU_n[u][j] += dn_pre_u · r_j · h_j

注意 dU_n 用的是 r_j（前一个隐藏单元的重置门），不是 r_u。这是实现中最容易写错的一处， 参数级梯度检验把它抓了出来（修复前误差 3×10⁻²，修复后 3×10⁻¹⁰）。

7.4 自注意力

Q = X W_Q,  K = X W_K,  V = X W_V
S = Q Kᵀ / sqrt(d)
A = softmax_row(S)
O = A V

Softmax 反向（逐行）：

dS = A ⊙ (dA - (dA ⊙ A) · 1ᵀ)
dS ← dS · scale
dQ = dS K
dK = dSᵀ Q
dV = Aᵀ dO

causal=true 时，第 t 行只对 0..t 做 softmax，被屏蔽列的概率为 0、梯度为 0。 测试验证了 t=0 的输出对 t>0 的输入扰动完全不敏感（差 ≤ 10⁻¹²）。

复杂度：O(B T² d) 时间、O(B T²) 概率矩阵。T 从 8→64（8×），实测耗时 0.35→4.08 ms （约 11.6×），接近二次增长。

RNN/GRU/LSTM 的耗时随 T 近似线性（LSTM 2.48→13.06 ms），注意力则呈二次曲线； 在 T≈64 时注意力已接近 LSTM 的成本，但它的优势是任意两位置的最短路径为 1， 而不是吞吐。

7.5 SequenceNetwork

BSF → [LSTM | GRU | RNN | SelfAttention]* → SequencePool(LAST|MEAN) → Dense → BC
  • LAST：取最后时间步；MEAN：对时间平均。反向分别做路由与均分。
  • 损失：CCE（要求 SOFTMAX 头）、BCE（要求 SIGMOID 头）、MSE。
  • 训练：前向 → 损失梯度 → 头反向 → 池化反向 → 序列层逆序反向 → 全局范数裁剪 → 逐参数更新。
  • 小批量：沿 batch 轴切片，时间/特征轴不变；epoch 损失按样本数加权。
  • 裁剪：||g||₂ > clip 时全体梯度乘以 clip/||g||₂，防止 BPTT 梯度爆炸。

7.6 梯度检验

GradientCheck 使用中心差分：

L(θ) = <upstream, f_θ(x)>
∂L/∂θ_i ≈ (L(θ_i + ε) - L(θ_i - ε)) / (2ε)

相对误差分母为 max(1, |analytic| + |numeric|)，避免小梯度被放大。 参数检验按均匀间隔抽样（默认每参数 8 个），输入维度全量检验。

loss: 0.6936 → 0.00156

8.2 两种读取器

BatchStream（顺序）

  • FileChannel 读入 direct ByteBuffer，容量 = batchSize × recordBytes；
  • 用 ByteBuffer.asDoubleBuffer() 做批量 get(double[], off, len)，而不是逐元素

getDouble()；

  • Batch、features[]、labels[]、ByteBuffer 在流生命周期内只分配一次；
  • rewind() 回到文件头，缓冲区保留。

MappedBatchStream（映射 + 洗牌）

  • FileChannel.map(READ_ONLY) 映射整个文件；
  • DoubleBuffer.get(sourceIndex, dst, offset, length) 绝对批量读，一个 epoch 零系统调用；
  • int[] order 做行置换，洗牌不移动数据；
  • rewind() 递增 epoch 并按 seed + epoch×1000003 重新洗牌；
  • 同样复用 Batch 与数组。

8.3 实测

模式批次吞吐每行分配
顺序40961 539.7 MiB/s1.48 B
顺序10241 130.2 MiB/s0.37 B
映射10241 074.4 MiB/s4.38 B
映射 + 洗牌4096345.7 MiB/s5.48 B

结论：

  1. 每行分配 ≈ 0。测量到的 0–5.5 B/row 是 JIT/安全检查的噪声，不随数据集增大而增长。

next() 的契约是“不分配 Batch、数组或缓冲区”，测试用对象身份断言验证。

  1. 顺序读取已经接近页缓存带宽，映射读并没有更快；映射的价值在于零系统调用与**随机

访问能力**（洗牌）。

  1. 洗牌慢约 3×，因为行置换破坏了顺序预取，属于预期的缓存代价。对训练 epoch 而言，

这个代价通常值得。

8.4 GC 分析

推理/训练热路径上的临时对象主要来自：

位置是否可避免现状
DataLoader next()是已复用全部缓冲
张量 forward 输出部分每层返回新 Tensor（API 语义要求）
LSTM/GRU/Attention 工作区是按 shape 缓存并复用
直方图工作区是单数组切片，无节点级分配
树节点否每个节点一个对象，训练期一次性
序列化 payload是单 ByteBuffer，无逐元素流

LSTM/GRU/Attention 的 hidden/cell/gate/probability 数组在 shape 不变时不再分配； GradientCheck 与 SequenceNetwork.fit 的小批量切片是显式拷贝，属于训练期可控成本。

9. 模型序列化

9.1 容器

0   int    magic = 0x42534C54
4   int    version = 2
8   int    kind（稳定码）
12  int    payload length
16  long   CRC32C(payload)
24  byte[] payload

保存：ModelWriter 在堆上增长 ByteBuffer，putDoubles 通过 DoubleBuffer 视图批量写； 最后一次性 FileChannel.write。

加载：FileChannel.map(READ_ONLY)，在映射区上直接算 CRC32C，校验通过后把剩余区域 slice() 给 ModelReader，不复制 payload。

校验项：magic、版本、kind 范围、payload 长度与文件大小一致、CRC、枚举序号、数组长度、 树深度上限（10 000）、层数上限、分类类别非空、Flatten 拓扑。

9.2 覆盖范围

CNN、HistogramGradientBoosting、RandomForest、KMeans、PCA、 GaussianNaiveBayes、LSTM、GRU、VanillaRNN、SelfAttention、SequenceNetwork。

所有模型在测试中做“保存 → 加载 → 预测”的逐比特比较（Double.doubleToLongBits 或 Arrays.equals）。载荷覆盖 CNN 卷积核、GBDT 树结构、PCA 主成分、LSTM 的三组权重等 全部可训练/可推导状态，因此预测一致即意味着这些状态被完整恢复。

10.3 静态审查发现并修复的问题

  1. GRU 重置门耦合错误：dU_n 误用当前单元的 r_u，应为前单元的 r_j；梯度检验

误差 3×10⁻² → 3×10⁻¹⁰。

  1. GRU 隐藏梯度覆盖：currentHidden[u] = dh·z 覆盖了之前单元写入的 U_zᵀdz 贡献；

改为 +=。

  1. 分类标签排序：TreeMap 的插入序号不等于排序序号，导致 classes 非升序，

Arrays.binarySearch 在森林预测中失败；改为先收集排序标签再重映射。

  1. PCA 特征向量旋转：初版旋转只更新了部分行/列；改为对 V 的所有行应用

V ← V·J(p,q,θ)。

  1. 分箱候选数：循环上界误用 candidates.length，小样本时只生成一个阈值；改为

maxBins-1 并限制写入数量。

  1. 重要性归一化：部分树无分裂时森林重要性和小于 1；改为按总和归一化。
  2. 模型长度溢出：payload + 24 可能溢出 int；加入上界检查。
  3. DataLoader 逐元素解码：改为 DoubleBuffer 批量读，去掉每个元素的字节序转换与

边界检查；流式吞吐达到 1.54 GiB/s。

12. 设计取舍

  1. 为什么坚持零依赖：依赖会把“数值行为”交给第三方版本；本项目的目标是让每个公式、

每个内存布局都可审计。代价是要自己实现断言、CSV、序列化与特征分解。

  1. 为什么用 double[] 而不是 Panama/off-heap：JDK 21 的 Vector API 对 double[] 的

支持最成熟；off-heap 需要 MemorySegment 与生命周期管理，收益主要在超大模型。 当前上限（20 亿元素）覆盖了目标场景。

  1. 为什么用 ForkJoin 而不是虚拟线程：计算任务是 CPU-bound、细粒度、递归分治；

虚拟线程解决的是阻塞 I/O 的线程成本，不适用于此处。

  1. 为什么用 byte 分箱：255 个桶足够表达直方图精度，byte[] 让 5000×64 的分箱矩阵

只有 320 KB，能留在缓存；无符号读取避免 Java 的 signed byte 陷阱。

  1. 为什么 Jacobi 而不是幂迭代：PCA 需要全部特征值/向量来做解释方差与白化；

幂迭代只给 top-1，需要 deflation 且数值稳定性差。Jacobi 对小 p 精确且实现简单。

  1. 为什么 Gram 限制 20 000 行：n² 的 double 矩阵在 20 000 行时约 3.2 GB，

超过常见堆；再大应使用随机化 SVD 或外存算法。

13. 局限与下一步

  1. GBDT 多分类：当前只有平方误差与二分类逻辑损失；softmax 多分类需要每类一棵树

与 softmax 梯度，是下一步首要功能。

  1. 跨节点并行：树生长仍是递归串行，只并行节点内直方图；按层并行 + 每线程工作区

有望把 2.39× 提升到 4× 以上。

  1. 稀疏数据：Matrix 是稠密存储；高维稀疏场景需要 CSR/CSC 与稀疏直方图。
  2. 注意力：单头、无位置编码、无 dropout；causal 只是掩码。多头与位置编码是自然扩展。
  3. 序列标注：SequenceNetwork 只做池化分类；逐时间步输出需要 Layer<BSF,BSF> 头

与逐时间步损失。

  1. PCA 规模：Jacobi O(p³)、Gram O(n²)；十万级特征需要随机化算法。
  2. 基准：非 JMH，缺少 fork 隔离与 GC 控制；下一步可接入 JMH 做回归门禁。
  3. 序列化：payload 一次性构造，超大模型受 2 GiB 数组上限约束；流式写入是后续优化。

15. 结论

Basalt 2.0 已经形成一条完整、可验证、零依赖的机器学习链路：

  • 广度：从线性模型到直方图提升、森林、聚类、PCA、朴素贝叶斯；
  • 深度：从 CNN 到 LSTM/GRU 的 BPTT、注意力反向、端到端序列训练；
  • 速度：SIMD 矩阵乘 56.5×、森林 4.8× 线程扩展、数据管线 1.54 GiB/s 且近零分配；
  • 可信：30 组测试、5 个编译期拒绝、参数级梯度检验 ≤3×10⁻¹⁰、全模型逐比特往返。

真正的工程价值不在于“每个算法都存在”，而在于每个公式都能被数值检验、每个失败都能 在编译期或入口处暴露、每个性能数字都能被脚本复现。这三件事，本轮已经做到。
