Basalt — Java + Rust Machine Learning Runtime

Maven coordinates — io.github.9178nekomc:basalt:3.5.0
Runtime — Java 21 (--add-modules jdk.incubator.vector) + bundled Rust native library
One dependency, no Python, no GIL, no manual native build on Windows x86_64. Docs — <https://9178nekomc.github.io/basalt/>

English

Install

<dependency>
    <groupId>io.github.9178nekomc</groupId>
    <artifactId>basalt</artifactId>
    <version>3.5.0</version>
</dependency>

Build and install locally from source:

mvn clean install

The shaded, self-contained artifact is basalt-3.5.0-all.jar (classifier all). It contains the Windows x86_64 native runtime; other platforms can add their own native/<os>-<arch>/ library or point -Dbasalt.native.path at a locally built one.

QuickStart — 10 lines, forward + backward

try (Basalt engine = Basalt.create()) {
    Tensor x = engine.randn(32, 8);
    Tensor y = engine.randn(32, 1);
    Linear hidden = engine.linear(8, 16);
    Linear output = engine.linear(16, 1);
    Tensor loss = output.forward(hidden.forward(x).relu()).mse(y);
    loss.backward();
    System.out.println(loss.data()[0]);
}

KNN classification

Matrix x = Matrix.fromRows(new double[][]{{0, 0}, {0, 1}, {1, 0}, {1, 1}});
double[] y = {0, 1, 1, 0};
Estimator knn = KNearestNeighbors.builder().k(3).build().fit(x, y);
double[] prediction = knn.predict(x);

Random forest

RandomForest forest = RandomForest.builder()
        .trees(100)
        .maxDepth(8)
        .seed(42)
        .build()
        .fit(x, y);
double[] prediction = forest.predict(x);

Hand-written CNN

try (Basalt engine = Basalt.create()) {
    Tensor images = engine.tensor(pixels, 64, 1, 28, 28);
    Tensor labels = engine.tensor(targets, 64);
    Sequential<BCHW, BC> cnn = engine.<BCHW>sequential()
            .add(basalt.conv2d(1, 8, 3, 1, 1))
            .add(engine.activation(Activation.RELU))
            .add(new MaxPool2d(2))
            .add(new Flatten())
            .add(engine.linear(8 * 14 * 14, 10));
    var lossFunction = engine.crossEntropy();
    var optimizer = engine.adamw(cnn.parameters(), 1e-3f);
    for (int step = 0; step < 100; step++) {
        Tensor loss = lossFunction.loss(cnn.forward(images), labels);
        loss.backward();
        optimizer.step();
        optimizer.zeroGrad();
        engine.clearGraph();
    }
}

Why Basalt

  • Rust at the bottom: AVX2/FMA GEMM, im2col convolution, rayon parallelism. No Python interpreter, no GIL, no per-op FFI marshalling.
  • Eager tensor API: Tensor, Module, Sequential, AdamW, CrossEntropyLoss, stateDict, multi-head attention — every op runs immediately and records a graph node.
  • Compile-time safety Python cannot match: Sequential<I,O> closes the layout chain at javac time; Conv2d → Linear is a compile error, not a runtime shape exception.
  • One dependency: Java 21 + one Maven coordinate. The native library is extracted from the jar and loaded automatically.
  • Observability: basalt.NativeQueue JFR events record every command-queue execution with op count, bytes, duration and stack trace.
  • Three depths, one library: Auto.quickstart(x, y) screens the whole catalogue and returns a scored model; Zoo + Trainer compose and train an architecture; Module + Registry let you write a layer or an algorithm the library has never seen.

Runtime note: add --add-modules jdk.incubator.vector to your application JVM arguments. For Maven Surefire: <argLine>--add-modules jdk.incubator.vector</argLine>.

中文文档

Basalt 是一个 Java 调度、Rust 计算的机器学习运行时：eager 张量、动态计算图、反向传播、原生 CNN/Transformer 算子、AdamW、JFR 事件流，以及经典统计学习估计器。 Java 21 负责 API、校验、类型安全与编排；性能敏感的算子、张量生命周期和反向传播由 Rust 持有。

设计取向是：上手像写脚本，执行像编译产物。动态形状与即时执行由 Java 泛型、 Sequential<I,O> 布局链和编译期检查兜底；重计算全部下沉到 Rust，两层之间只留一层 128 字节的零拷贝指令队列；观测交给 JVM 内置的 JFR，不需要额外插桩。

  • 语言/运行时：Java 21（--release 21，jdk.incubator.vector）+ Rust 原生内核（JNI）
  • 依赖：Java 侧 0；原生侧 jni + rayon + slotmap + matrixmultiply（./native-build.sh）
  • 构建：Maven 3.9+（mvn clean install）或 javac + cargo + bash；无 Gradle
  • 验证：16 个 Rust 单元测试 + 66 组 legacy Java 套件 + 12 个 JUnit 5 SDK 测试
    • 6 个编译期拒绝用例 + -Xlint:all（除 JDK incubating 提示外零告警）
  • 文档：《Basalt 终极架构与性能基准测试报告》
  • API 参考：docs/index.html（离线可读）

文档是怎么生成的

签名不允许手写，说明不允许自动编造，因此拆成三步：

# 1. 扫描源码，提取精确签名、参数名、抛出子句 → build/api/api.json
python tools/api_dump.py --src src/main/java --out build/api/api.json

# 2. 按模块切出待填骨架（供撰写说明时对齐 key）
python tools/make_briefs.py --api build/api/api.json --out build/api/briefs

# 3. 合并骨架与说明，渲染文档站点
python tools/build_api_docs.py --api build/api/api.json \
    --docs 'tools/docs_data/g*.json' --out docs

# 4. 冒烟测试：标签闭合、id 唯一、链接与锚点可达、无占位符
python tools/check_docs.py --root docs
  • tools/api_dump.py：掩码扫描（注释/字符串置空但保留偏移）+ 深度成员切分，能识别嵌套类型（RandomForest.Builder）、枚举常量、record 组件、泛型方法与 throws。
  • tools/docs_data/g*.json：说明数据层，契约见 tools/docs_data/SCHEMA.md。渲染器按 (qualified, key) 匹配，匹配不上的说明直接丢弃并报错，所以文档不可能描述一个不存在的参数。
  • tools/build_api_docs.py：零外部依赖渲染器，输出 13 个 HTML 页，另加一份 readme.html。 每页自包含：CSS、主题/搜索脚本、1700 条搜索索引全部内联，不引用任何外部 _static/ 目录——静态托管（Jekyll、各类预览服务）会跳过下划线开头的目录，外部资源一旦 404，页面就会退化成无样式纯文本。
  • tools/md_render.py：README 的 Markdown 渲染器（标题、围栏代码、GFM 表格、嵌套列表、引用块、行内标记），CJK 换行不插空格，java 代码块复用同一套高亮。
  • tools/check_docs.py：退出码非 0 即视为文档损坏，可用于 CI 门禁。

0.5 三层 API

同一个库，三种介入深度。三层共用同一套张量、同一张计算图，所以上一层永远不限制下一层。

第一层：一行跑起来

AutoModel model = Auto.quickstart(features, labels);   // 自动判断分类还是回归
System.out.println(model.summary());                    // 候选表 + 留出成绩
double[] prediction = model.predict(unseen);

它做的四件事：判断任务 → 用 5 折交叉验证把该任务下注册过的算法全部跑一遍 → 取最优者在全量数据上重训 → 在 25% 留出集上报分。要控制细节就换成 builder：

AutoModel model = Auto.builder(features, labels)
        .folds(10)
        .testFraction(0.2)
        .candidates("random_forest", "gradient_boosting")
        .fit();

第二层：拼装与训练

try (Basalt engine = Basalt.create()) {
    Sequential<BC, BC> net = Zoo.tabularClassifier(engine, 4, 3);   // 或 Zoo.mlp / Zoo.cnnClassifier
    Trainer.of(engine.context(), net, engine.adamw(net.parameters(), 1e-2f), engine.crossEntropy())
            .epochs(50)
            .batchSize(16)
            .earlyStopping(5)
            .fit(engine.tensor(features, rows, 4), engine.tensor(labels, rows));
}

Zoo 返回的是普通 Sequential，可以继续 add；Trainer 就是手写循环的封装——前向、损失、反向、更新、清梯度、清图，一步不省，所以训出来的模型和手写循环完全一致。

第三层：手写一切

一个层只需要满足 Module 的两个方法：

final class MyLayer extends Module<BC, BC> {
    private final Tensor weight = Tensor.parameter(context, 128, 64);

    @Override
    public Tensor forward(Tensor input) {
        return input.matMul(weight).tanh();
    }

    @Override
    public List<Tensor> parameters() {
        return List.of(weight);
    }
}

写好的层能塞进 Sequential，也能直接交给 Trainer，因为 Trainer 只认 Module。算法层面同理——实现 Estimator 并注册，Auto 立刻把它纳入筛选：

Registry.register("my_regressor", Task.REGRESSION, MyRegressor::new);
Auto.quickstart(features, targets);   // 新算法与内置算法同台竞争，不需要改动库代码

这套组合支撑两种用法：用现有算子拼一个全新的结构（自定义层 + 自定义损失 + 自定义优化器， Trainer 照常训练、stateDict() 照常保存），以及换掉整个学习算法（注册自己的 Estimator，它马上和 23 个内置算法一起被交叉验证比较）。

3.7 原生张量与自动求导（专家层）

try (NativeContext ctx = NativeContext.create(8)) {
    NativeTensorHandle x = ctx.of(features, false, 256, 32);   // [batch, features]
    NativeTensorHandle w = ctx.random(new int[]{32, 64}, 42, 0.15f, true);
    NativeTensorHandle b = ctx.parameter(64);
    NativeTensorHandle z = ctx.zeros(256, 64);
    NativeTensorHandle a = ctx.zeros(256, 64);
    NativeTensorHandle h = ctx.zeros(256, 64);
    NativeTensorHandle target = ctx.of(labels, false, 256, 64);
    NativeTensorHandle loss = ctx.zeros(1);

    CommandQueueBuilder queue = new CommandQueueBuilder(ctx);
    queue.matMul(x, w, z)       // z = x W
         .add(z, b, a)          // a = z + b（b 按行广播）
         .relu(a, h)            // h = relu(a)
         .mse(h, target, loss)  // loss = mean((h - target)^2)
         .execute();            // 4 个算子，1 次 JNI

    ctx.backward(loss);         // 拓扑排序 + 逆序求导
    w.adam(1e-3f, 0.9f, 0.999f, 1e-8f, 0f, 1);
    b.adam(1e-3f, 0.9f, 0.999f, 1e-8f, 0f, 1);
    w.zeroGrad();
    b.zeroGrad();
    ctx.clearGraph();           // 下一轮独立前向之前必须清图
}

NativeMLP 是基于同一套 API 的完整参考实现：XOR（2-12-1）与线性回归都在 NativeTestSuite 中做收敛断言，梯度用中心差分逐参数校验。

§0.5 讲的是用法上的三层。同一件事在实现上也分成三层，越往下越接近金属：

层次入口拿到什么
门面Basalt、Auto、Estimator.fit/predict一次调用完成训练、预测、筛选
构件RandomForest.builder()、Zoo、Trainer逐个模块调参、替换求解器、控制线程与批次

越往下，能改的东西越多，需要自己保证的东西也越多。

3.8 eager 执行 API（basalt.torch）

try (NativeContext ctx = NativeContext.create(8)) {
    Sequential<BCHW, BC> net = Sequential.<BCHW>start()
            .add(new Conv2d(ctx, 1, 8, 3, 3, 1, 1, 1, 1, true, 42))
            .add(new Activation<BCHW>(Activation.Kind.RELU))
            .add(new MaxPool2d(2))
            .add(new Flatten())
            .add(new Linear(ctx, 8 * 14 * 14, 10));

    CrossEntropyLoss lossFunction = new CrossEntropyLoss();
    AdamW optimizer = new AdamW(net.parameters(), 1e-3f);

    for (int step = 0; step < 100; step++) {
        Tensor logits = net.forward(images);          // [N, 10]
        Tensor loss = lossFunction.loss(logits, labels);
        loss.backward();                              // Rust 拓扑排序 + 逆序求导
        optimizer.step();                             // AdamW，原生 bias correction
        optimizer.zeroGrad();
        ctx.clearGraph();                             // 下一轮独立图
    }
}
  • Tensor 是动态形状的 eager 张量：matMul、conv2d、maxPool2d、batchNorm2d、 layerNorm、softmax、crossEntropy、embedding、permute、reshape、dropout。
  • Module<I,O> 的布局标签是编译期的：Conv2d 是 BCHW → BCHW，Flatten 是 BCHW → BC，Linear 是 BC → BC。Sequential.<BCHW>start().add(new Linear(...)) 无法通过编译（InvalidTypedPipeline.java 是强制检查用例）。
  • MultiheadAttention / TransformerBlock 由同一套公开 API 组合：多头 reshape/permute、 batched matmul、causal mask、softmax、LayerNorm、GELU、残差。
  • stateDict() / loadStateDict() 提供权重往返；Optimizer.clipGradNorm() 在 Rust 侧做全局 L2 裁剪。

4. 原生 CPU 内核架构

4.1 所有权与生命周期

Java: NativeTensorHandle ──long ptr──┐
                                     │  JNI
Rust: Context                         ▼
        ├── SlotMap<TensorKey, TensorSlot>   ← 唯一所有者
        │       └── Arc<RwLock<NativeTensor>> ← Java 指针指向的分配
        └── Graph (Mutex)
  • 张量内存是 Vec<f32>，梯度 Vec<f32> 惰性分配；推理张量永远不付第二份缓冲区。
  • Arc::into_raw 把一份强引用交给 Java；Context 的 slotmap 保留另一份用于查找与兜底释放。
  • nativeReleaseTensor 先按地址查 slotmap，命中才 Arc::from_raw 并 drop。第二次释放查不到地址，返回 1（幂等），不会 double free。
  • Java 侧 NativeTensorHandle 只持 long，实现 AutoCloseable；Cleaner 注册的 State 用 AtomicLong 保证 close() 与 GC 兜底只会有一次真正释放。
  • NativeContext 用读写锁划定生命周期：所有 JNI 调用持读锁，close() 持写锁。 Tensor handle 强引用 context，因此 context 不可能先于 handle 被 GC。
  • 释放图内张量会清空当前计算图，避免地址复用后旧节点仍然指向新张量。

没有 Box::leak，没有全局张量池。唯一的进程级结构是 context 注册表，用于在 FFI 边界验证指针存活；它不持有任何张量数据。

4.2 指令队列

CommandQueueBuilder 把一批算子写进 ByteBuffer.allocateDirect，每条 32 字节：

偏移类型字段
0u8op code（1=MatMul, 2=Add, 3=ReLU, 4=Sub, 5=Mul, 6=Sigmoid, 7=Tanh, 8=MSE）
1u8[7]对齐填充，写零
8u64input A 的 native 指针
16u64input B 的 native 指针（一元算子为 0）
24u64output 的 native 指针

Rust 用 read_unaligned 逐条解析，在一次 JNI 调用内顺序执行并追加计算图节点。 Java 不循环调 JNI，也不把张量数据搬进 float[]；只有显式 data() / grad() 才发生拷贝。

4.3 SIMD 矩阵乘

前向 GEMM 严格采用 i -> k -> j，j 最内层：

for i in 0..M          // 每次处理 6 行，6 行 C 常驻 L1
  for k in 0..K        // 广播 a[i,k]
    for j in 0..N      // _mm256_loadu_ps / _mm256_fmadd_ps，8 路并行
      C[i,j] += a[i,k] * B[k,j]
  • B[k, :] 在 6 行之间复用；C 的 6 行约 24 KiB，和 B 的一行一起落在 32 KiB L1 内。
  • AVX2/FMA 在运行时检测；非 x86 或缺少 FMA 时自动走标量路径。
  • 512³ f32 实测 115 GFLOP/s、1024³ 109 GFLOP/s；相对 Java Vector API 的 double GEMM 分别为 3.2× / 2.53×，256³ 为 8.4×。
  • 反向传播使用 gemm_nt（dA = dC·Bᵀ）与 gemm_tn（dB = Aᵀ·dC），同样按行/列分块并行。

张量引擎使用 f32；经典估计器（Ridge/KMeans/GBDT/森林）仍使用 f64。这是刻意的分工：神经网络训练对 f32 足够，经典模型的数值证明与持久化保持 f64。

4.4 自动求导

  • 每个队列算子追加一个 Node { op, inputs, output, attrs }； attrs 记录 MatMul 的 (m,k,n) 或广播的输入形状。
  • nativeBackward(root) 从 root 反向收集可达子图，用 Kahn 算法做拓扑排序；逆序遍历，按 op_code 调用对应导数，梯度累加到每个输入的 grad。
  • 支持 MatMul、Add、Sub、Mul、ReLU、Sigmoid、Tanh、MSE； Add/Sub/Mul 支持 尾部广播，反向时对广播维求和。
  • 图在写入前校验：禁止 output == input、禁止重复生产同一张量、禁止覆盖已被消费的张量。这三条把“原地算子”和“地址复用”这类静默错误变成带上下文的异常。
  • 一轮训练结束后 Java 调 clearGraph()；NativeMLP 在每个 mini-batch 后执行 backward -> Adam -> zeroGrad -> clearGraph。

5.3 JVM 侧的四个结构性优势

  1. 编译期布局管线：Sequential<I,O> 用 Java 泛型把 BCHW → BC → BC 的链路钉死。动态语言只能在运行时抛 shape mismatch；Basalt 在 javac 阶段就拒绝。强制用例：src/test/compile-fail/basalt/tests/InvalidTypedPipeline.java。
  2. JFR 常开事件流：basalt.NativeQueue 记录每次队列执行的 op 数、字节数、耗时和完整调用栈。 JFR 是 JVM 内置的采样式剖析器，生产可热附加；Python 的 cProfile 是插桩式，吞吐减半。
  3. 零拷贝 + 无 GIL：Java 只持 long，32/128 字节指令直接读 ByteBuffer.allocateDirect； Rust 用 rayon 在原生线程池并行。没有 Python 解释器、没有 GIL、没有 per-op FFI 编组。
  4. Rust 所有权 + Java 生命周期：Arc<RwLock<>> + slotmap + Cleaner + 读写锁，双重释放/野指针/GC 漏释放都有测试。动态语言给不了这种内存安全保证。

5.4 已实现的训练栈能力

  • eager execution：每个 Tensor 操作立即执行并记录图节点；
  • 动态计算图 + 反向传播：Kahn 拓扑排序、梯度累加、广播反向；
  • nn.Module 组合：Sequential、Linear、Conv2d、BatchNorm2d、LayerNorm、 Dropout、Embedding、MultiheadAttention、TransformerBlock；
  • 优化器：SGD（weight decay）、AdamW（bias correction + decoupled weight decay）、全局 L2 梯度裁剪；
  • 损失：MSE、fused CrossEntropy；
  • stateDict() / loadStateDict() 权重往返；
  • 动态 shape、广播、reshape/permute/flatten。

5.5 尚未覆盖的（诚实边界）

  • CPU only：没有 CUDA/Metal/分布式；rayon 只吃本机核心。
  • 无稀疏/量化/AMP：CSR、int8、f16/bf16 未实现；张量引擎统一 f32。
  • Conv2d 简化：groups=1、dilation=1；MaxPool2d 无 padding。
  • 无算子融合编译器：有指令批处理和图捕获，但没有算子融合编译器； Tensor 每个 op 一次 JNI，专家可用 CommandQueueBuilder 手工批处理。
  • 单流图：同一 context 的图由锁串行化；并发训练用独立 context。

这些边界不影响“eager 张量 + 原生 autograd + CNN/Transformer”的定位，但决定了它现在不是 CUDA 训练框架的替代品。

偏移    类型      字段
0       int       magic = 0x42534C54 ("BSLT")
4       int       version = 2
8       int       kind (稳定枚举码，非 ordinal)
12      int       payload length
16      long      CRC32C(payload)
24      byte[]    payload
  • 保存：一次性构造 ByteBuffer，单次 FileChannel.write；
  • 加载：FileChannel.map(READ_ONLY)，CRC32C 直接在映射区上计算，不复制 payload；
  • 校验：magic、版本、长度与文件大小一致、CRC、枚举范围、数组长度上界、树深度上界；
  • 失败统一抛出 ModelFormatException（非受检），不会把损坏文件解释为合法模型。

9. 设计约束与已知边界

  1. 稠密内存模型：Matrix/Tensor 使用单个 double[]，上限约 20 亿元素；稀疏场景未优化。
  2. PCA 复杂度：Jacobi 为 O(p^3) 级旋转，Gram 为 O(n^2 p) 且限制 n ≤ 20 000；超大特征空间应改用随机化 SVD（未实现）。
  3. GBDT 目标：当前支持平方误差与二分类逻辑损失；多分类 softmax 未实现。
  4. 序列训练：SequenceNetwork 为分类头设计；序列标注（逐时间步输出）需要额外的输出层。
  5. 注意力：单头、无位置编码、无 dropout；causal 仅做掩码，不改变参数形状。
  6. 持久化：v2 不兼容 v1；ModelCodec 一次性构造 payload，超大模型（>1 GiB）会受数组上限约束。
  7. 基准：非 JMH，使用中位数与预热；结果只对当前机器/JDK 有效，运行间波动约 ±10%。
  8. 精度分层：原生张量引擎为 f32；经典估计器保持 f64。跨层比较需显式转换，不做隐式降精度。
  9. 计算图生命周期：一轮独立前向/反向结束后必须 clearGraph()；同一张量在同一图中只能被生产一次，原地算子会被拒绝。这是为了保证反向传播的 DAG 语义。
  10. 原生可选：经典模型在动态库缺失时完整回退 Java；basalt.nativebridge 的专家 API 需要原生库。
  11. HGB 直方图：会话路径使用 f32 交错桶累加部分和，最终增益扫描提升到 f64；参考数据上精度与 f64 路径一致（0.7981 / 0.8867），极端大样本场景可用 Java f64 路径对照。
  12. 线程模型：每个 NativeContext 持有按并行度缓存的 rayon 线程池；多个 context 并发时线程数会叠加，生产环境应共享 context 或限制线程数。
  13. 单流图：同一 context 的计算图是单流（队列执行与 backward 由图锁串行化）；并发训练/推理请为每个线程创建独立 context，或只做无图推理。
  14. 队列非事务：一批指令中途失败时，已执行的算子与图节点不会回滚；捕获异常后应 clearGraph() 并丢弃该批输出。
  15. Torch 边界：CPU only；Conv2d 目前 groups=1、dilation=1，MaxPool2d 无 padding；无稀疏/量化/混合精度/分布式，也没有 torch.compile 级算子融合编译器。

10. 许可

本仓库为教学/研究用途的独立实现，未复制任何第三方库代码。

11. v3.5.0 三期演进全景

第一阶段：夯实工程底座（Phase 1）

  1. JNI / Rust 底层核心工程强化
    • 双重内存安全 (Cleaner + AutoCloseable)：NativeContext、NativeTensorHandle 与 NativeKernels.HistogramSessionHandle 均支持 try-with-resources 确定性释放与 Cleaner 兜底回收。
    • 代数句柄校验（Generation-Tagged Handle）：原生层句柄采用 (generation << 32) | slot_index 编码，释放后 slot 递增代数，彻底杜绝悬垂指针与 ABA 复用引发的 JVM 崩溃。
    • 跨平台预编译与 CI/CD：NativeKernels 自动识别 windows-x86_64、linux-x86_64、linux-aarch64、macos-x86_64、macos-aarch64 并从 Classpath 提取原生库；配备 .github/workflows/ci-release.yml 多平台自动构建流水线。
    • 线程安全与异常体系：CommandQueueBuilder 全方法同步化保护；JNI 边界捕获所有 panic 并映射为结构化异常体系（BasaltExceptionCode、BasaltParameterException、BasaltShapeException、BasaltMemoryException、BasaltUnsupportedOperationException）。
  2. ML 基础设施工具（预处理、模型选择、管线）
    • 数据预处理：Transformer 接口、StandardScaler、MinMaxScaler、OneHotEncoder、LabelEncoder、SimpleImputer（支持 MEAN / MEDIAN / MOST_FREQUENT / CONSTANT），全部支持 inverseTransform 与 .bsl 序列化。
    • 模型选择与超参搜索：DataSplit（Basalt.trainTestSplit 含分层抽样）、KFold、StratifiedKFold、GridSearchCV、RandomizedSearchCV。
    • Pipeline 管线：basalt.ml.Pipeline 支持任意 Transformer 序列串联终端 Estimator，一键完成训练、推理、评分及 .bsl 原子二进制持久化。
  3. 质量保障体系
    • 9 大测试套件（含 Phase1TestSuite、Phase2TestSuite、Phase3TestSuite）+ 6 个编译期安全拒绝测试 + 2,000 次循环张量分配/释放零泄漏验证 + ./benchmark.sh 可复现基准。

第二阶段：补齐核心能力（Phase 2）

  1. 经典 ML 算法扩展
    • 核方法：Kernel（LINEAR / RBF / POLY / SIGMOID）、非线性 SVC（SMO 求解器 + Platt 概率校准）、KernelRidge（Cholesky 对偶求解）、KernelPCA（双中心核特征分解）。
    • 无监督学习：GaussianMixture（全协方差 EM + log-likelihood / AIC / BIC）、AgglomerativeClustering（WARD / COMPLETE / AVERAGE / SINGLE）、IsolationForest（异常分数与离群点检测）、KernelDensity（Gaussian / Tophat / Epanechnikov 核密度估计）。
    • 特征工程：SelectKBest（ANOVA_F / PEARSON_CORR / MUTUAL_INFO）、RFE（递归特征消除）、PolynomialFeatures（任意阶多项式与交互项）、KBinsDiscretizer（等宽 / 分位数分箱，支持序号与独热输出）。
  2. 深度学习能力升级
    • 算子与层：Conv2d 支持分组卷积（groups）与空洞卷积（dilation）；新增 DepthwiseSeparableConv2d、GroupNorm；新增 L1Loss、SmoothL1Loss、BCEWithLogitsLoss 及 LEAKY_RELU、ELU 激活函数；完善 Dropout / BatchNorm2d 的 train() / eval() 状态切换。
    • DAG 计算图 (ComputationGraph)：突破 Sequential 线性限制，支持残差连接（addAddVertex / addSubVertex / addMulVertex）及多输入多输出拓扑排序前向与反向传播。
    • 训练基础设施：LRScheduler（CosineAnnealingLR、StepLR）、全局梯度裁剪 clipGradNorm、梯度累积 Optimizer.stepAccumulated(accumulationSteps)、以及包含模型权重+优化器动量+调度器状态的 Checkpoint 断点续训。
  3. 生态互通（ONNX 导入与导出）
    • OnnxModel 与 OnnxConverter 提供零外部依赖的 onnx.proto3（IR v8, Opset 17）解析与编码器，支持导出 Basalt 经典模型/管线与深度学习模块至标准 .onnx 文件（可直接被 Python onnxruntime 加载推理，误差 < 2e-6），并支持将外部 .onnx 模型直接加载进 JVM 原生执行。

第三阶段：打造差异化竞争力（Phase 3）

  1. 模型可解释性（Explainable AI）
    • FeatureImportance：树模型杂质重要度、线性模型归一化权重重要度、以及模型无关的置换特征重要度（permutationImportance）。
    • ShapExplainer：精确 LinearSHAP 与基于联盟采样的 TreeSHAP / KernelSHAP，严格满足局部可加性公理 $\sum_{j=1}^p \phi_j(x) + \phi_0 = f(x)$。
    • LimeExplainer：局部指数核加权 Ridge 代理模型，输出局部特征归因权重与局部拟合优度 $R^2$。
  2. 可观测性增强（JFR + 标准指标输出）
    • 新增 JFR 事件：NativeQueueEvent、OperatorExecutionEvent、NativeMemoryEvent。
    • BasaltMetrics：无锁记录算子调用次数、耗时分位数（p50 / p95 / p99）、吞吐量（ops/s、elements/s）与堆外/JVM 内存占用，支持一键导出 JSON 与 Prometheus 文本格式。
